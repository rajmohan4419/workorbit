# Finance reliability release verification

Base inspected: clean `main` at `ae5623d0ee6964325f3aac949141db893896fdeb`. No repository `AGENTS.md` was present. Implementation branch: `fix/finance-reliability-release`. No merge, push or deployment was performed.

## Confirmed defects and changes

- `src/tools/finance/gstrReconciliationEngine.js`: taxable-only matching ignored tax differences; malformed amounts became zero or partially parsed; invalid dates passed through; duplicate candidates selected the first row. Matching now compares taxable value and each available IGST/CGST/SGST/cess component, distinguishes missing tax from zero, preserves identifiers/references, holds ambiguous groups, rejects invalid rows, and returns deterministic row accounting. Unique punctuation variants remain supported and explicitly flagged for confirmation, preserving existing normalization behavior.
- `src/engines/bankReconciliationEngine.js`: positive signs overrode DR/CR; invalid separate debit/credit combinations were accepted. Explicit direction now wins with separate bank/ledger conventions and conflict checks. Existing scored matching, ambiguity flags and transaction reuse prevention remain in place. Exact-reference matching and description-based matching retain their existing scope, documented in reports.
- `src/engines/excelEngine.js`: ordinary monetary values in the date-serial range were interpreted as dates. Serial conversion is now restricted to date-named columns. Finance imports additionally use explicit mapping and date validation.
- `src/components/tools/FinanceFileImport.jsx` and `src/engines/financeImport.js`: staged local imports with sheet/header selection, mapping confirmation, preview, accepted/rejected counts, inline errors, limits, cancellation, per-source clearing and synthetic templates. Sources change only on confirmation. Failed replacements preserve active data.
- `src/tools/finance/GstrReconciliation.jsx` and `src/tools/business/BankReconciliation.jsx`: empty initial workspaces; explicit demo mode; real-source activation clears both demo counterparts and demo bank balances; both sources required for reports. Zero-day bank tolerance is preserved. Financial contents and identifiers are not logged; invoice identifier telemetry was removed from the invoice component.
- `src/engines/financeReports.js`, both reconciliation components, and `src/data/toolContent.jsx`: factual file-only wording and eligibility limitation; exports include source labels, row references, tolerances, component differences, rejects, ambiguity and scope. Spreadsheet text remains literal; formula-looking strings have no formula property in XLSX.
- `src/tools/business/gstInvoiceEngine.js`, `GstInvoice.jsx`, `GstInvoice.css`, `gstInvoicePdf.js`: explicit place of supply drives domestic tax split; state contradictions and local GSTIN checksum/format checks; shared totals; required/finite input checks; stable accessible form labels; full description wrapping; multipage PDF with repeated headers, reserved totals and signatures; ordinary rows stay together. Compact controls and horizontal table scrolling are preserved, with calculated cells able to expand.

Existing route definitions, hidden Business Portal/Market Lab status, payment configuration and entitlement policies were preserved. No government data retrieval, GST APIs, portal authentication, subscription plans or new paywalls were introduced.

## Limits and next milestone

See `finance-import-scope.md`. JSON supports only OrbitBoard normalized `orbitboard-gstr2b/1`, not raw GST portal JSON. PDF's bundled Helvetica font supports WinAnsi; unsupported characters require changing the text or printing the browser preview with a suitable local font. This ordinary domestic invoice workflow excludes special supply rules. Bank matching remains a review aid, and its adjustment classifications are assumptions. GSTR matches do not establish ITC eligibility.

This verification does not establish production readiness. Next milestone: put the synthetic browser/export scenarios into CI and conduct a controlled file-compatibility pilot before subscription work. Native font embedding and separately specified raw portal JSON adapters can be considered in that milestone.
